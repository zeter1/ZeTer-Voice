# Работа с ZeTer Voice

## Перед изменением

1. Открой чат из папки с `ZeTer Voice.py`, `tts_app/` и `tools/verify.py`. При сбое установи, какой экземпляр создал лог и где лежат его данные. [Исходники, Git и EXE](docs/PROJECT.md#копии-программы)
2. Начни с [карты по симптомам](docs/CODEMAP.md#куда-идти-по-симптому). Для поиска по коду используй `python -B tools/where.py WindowsCopyCapture` или `rg -n "WindowsCopyCapture" tts_app tools`. В `_maintenance_backups/` лежат старые копии кода. Открывай их для сравнения версий или отката.
3. Для сбоя установи этап и последний подтверждённый результат. Сопоставь логи, код и сценарий, который отличает причину от других объяснений. Если нужен повтор операции, привяжи его к подтверждённому временному отказу, ограничь по времени и проверь итог.
4. Меняй только нужное поведение. Сохраняй пользовательские правки, существующие форматы состояния, совместимые импорты и контракты вызывающего кода. Выбирай небольшой обратимый патч с проверяемым результатом.

## Данные и запуск

- `Настройки программы/`, `Текст/`, `Логи проблем/`, `Движки речи/` и `_maintenance_backups/` содержат рабочие данные, установленные движки или резервные копии. Для изменений исходников переносить только проверенные файлы из списка изменений. Порядок резервирования описан в [инструкции обновления](ОБНОВЛЕНИЕ_ИНСТРУКЦИЯ.txt).
- Импорт `runtime_storage.py` вычисляет папки от `__file__` или `sys.executable` и создаёт пробный файл `.write_test`. До импорта, теста или запуска используй [изолированную копию исходников](docs/VERIFICATION.md#изолированная-копия-исходников). Смена `cwd` или `TEMP` сама по себе не изолирует данные.
- Для проблем сохранения проверь сохранённые вкладки, файлы текста, `workspace.recovery.json` и архивы только в пределах нужного сценария. Повреждённые и недоступные файлы сохраняй для восстановления. Прежде чем менять сохранение, закрытие или очистку, сверяй [контракт данных](docs/PROJECT.md#постоянные-данные).

## Архитектурные границы

- `ZeTer Voice.py` — точка запуска и фасад совместимости. `runtime.py`, `sapi.py`, `windows_tools.py`, `problem_logger.py` и составные mixin-модули сохраняют точки импорта. Поведение меняется в [его владельце](docs/CODEMAP.md).
- Изменения виджетов, Tk-переменных и жизненного цикла окна выполняются в главном потоке Tk. Фоновые события привязываются к нужной вкладке, поколению горячей клавиши или идентификатору запуска. Перед применением результата проверяй, что его получатель ещё актуален. [Архитектура и потоки](docs/ARCHITECTURE.md)
- При изменениях захвата защищай привязку снимка Unicode к исходному окну и назначенной вкладке. При изменениях чтения или MP3 защищай [условия подтверждения результата](docs/PROJECT.md#чтение-и-создание-mp3).
- Бюджет модулей задан в `tools/verify_structure.py`. Карты символов и размеров в `docs/` создаёт `tools/build_code_index.py`. Для сложных изменений MP3 используй этапы в [WORKER_MAP.md](docs/WORKER_MAP.md).

## Диагностика и проверка

- Выбери сессию по времени сбоя, сверь её происхождение по полям `session.json`, затем проверь целостность записи в `AI_READ_FIRST.json`. При необходимости найди событие по `capture_id`, `preview_run_id` или `run_id`. [Как читать логи](docs/LOGGING_FOR_AI.md#порядок-чтения)
- Для сбоя F8 сверяй `clipboard_source_check` и `clipboard_busy_opener`. Окно, открывшее буфер, может отличаться от владельца содержимого. Для `capture_busy` читай итог захвата по `blocked_by_capture_id`.
- Храни в примерах и тестах вымышленные тексты и файлы. При диагностике выводи только поля, нужные для вывода. Для принятого исправления по логам добавь одну запись в журнал `Логи проблем/Исправления.md` и сохрани исходную сессию.
- Используй ближайшие проверки из [руководства по проверке](docs/VERIFICATION.md), затем общий `python -B tools/verify.py` в отдельной копии. Для изменений документации сверь команды и локальные ссылки. Результаты SAPI, горячей клавиши, реального устройства и EXE подтверждаются отдельными запусками.
- В конце укажи изменённые файлы, проверенный сценарий и границы `NOT_VERIFIED`. Историю принятой правки запиши одним блоком с датой и смещением UTC в [CHANGELOG.md](CHANGELOG.md).
